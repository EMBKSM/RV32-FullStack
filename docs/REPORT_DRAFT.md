## Ⅰ. 프로젝트 실행 동기 및 목적

### 1.1 프로젝트 동기
컴퓨터구조 수업에서 CPU의 파이프라인·캐시·명령어 처리를 배우면서, 책으로만 보던 프로세서 내부 동작을 직접 만들어 보고 싶었다. 특히 최근 빠르게 확산되는 개방형 명령어집합 RISC-V는 로열티가 없고 사양이 공개되어 있어 학습용으로 직접 구현하기에 적합했다. 단순히 시뮬레이션에 그치지 않고, FPGA 보드에 올린 "내가 만든 CPU"가 PC에서 입력한 어셈블리를 실제로 실행하고 결과를 돌려주는 것까지 눈으로 확인하고 싶다는 것이 출발점이었다.

### 1.2 프로젝트 목적
RV32I 명령어집합을 지원하는 5단 파이프라인 소프트코어 CPU를 직접 설계·검증하고, 이를 Zynq-7000(Zybo Z7-20) FPGA에 SoC 형태로 올려 **PC에서 어셈블리를 입력 → UART 전송 → 하드웨어 CPU가 실행 → 레지스터 변화 회신**하는 풀스택 시스템을 완성하는 것이 목적이다. 나아가 보드의 모든 Pmod 핀을 메모리맵 주변장치(SPI·I2C·UART·PWM·GPIO)로 노출하여, 어셈블리만으로 외부 장치를 제어할 수 있는 확장형 플랫폼으로 발전시키는 것을 목표로 한다.

## Ⅱ. 프로젝트 배경

### 2.1 현재 트렌드, 배경
- **RISC-V의 부상**: 개방형·로열티 프리 ISA로 학계·산업 전반에서 채택이 급증하고 있으며, 교육·연구용 오픈소스 코어가 활발히 공개되고 있다.
- **소프트코어/FPGA 프로토타이핑**: ASIC 제작 전 단계에서 FPGA에 CPU를 올려 검증하는 방식이 보편화되었고, 엣지·임베디드 영역에서 용도에 맞춘 커스텀 코어·가속기 수요가 늘고 있다.
- **하드웨어-소프트웨어 통합 학습**: HDL 설계와 어셈블리/펌웨어를 한 흐름으로 다루는 풀스택 임베디드 역량이 중요해지고 있다.

### 2.2 기제품과의 차별성 (고객의 범위, 욕구)
- **직접 설계한 코어**: 기성 소프트코어(MicroBlaze, PicoRV32 등)를 가져다 쓰는 대신, 5단 파이프라인 + 명령/데이터 캐시(I$/D$) + AXI4 메모리 + Zicsr/트랩/FENCE.I를 직접 RTL로 구현했다.
- **풀스택 실행 환경**: PC 어셈블러(GUI/콘솔) ↔ PS 모니터(베어메탈) ↔ PL CPU를 잇는 적재·실행·디버그 경로를 직접 구축해, JTAG 없이도 UART만으로 프로그램을 돌리고 레지스터를 본다.
- **골든모델 검증**: 명령어 집합 시뮬레이터(ISS)와 비트 단위로 대조하는 회귀 검증으로 신뢰성을 확보했다.
- **모든 Pmod의 주변장치화**: JA~JE 40핀을 MMIO 주변장치로 노출하여, 어셈블리 `sw`/`lw`만으로 SPI/I2C/UART/PWM/GPIO를 직접 제어한다(기성 코어에 없는 확장).
- **고객 범위/욕구**: 컴퓨터구조·디지털논리 학습자, 임베디드 입문자. "CPU 내부를 직접 만들고, 만든 CPU로 실제 하드웨어를 제어해 보고 싶다"는 욕구를 충족한다.

### 2.3 프로젝트 기대효과
- CPU 마이크로아키텍처(파이프라인·해저드·포워딩·캐시)에 대한 깊은 이해.
- 어셈블리 한 줄이 실제 게이트에서 동작하는 과정을 눈으로 확인하는 교육 도구.
- 주변장치를 자유롭게 붙일 수 있는 확장형 SoC 플랫폼 기반 확보.

## Ⅲ. 프로젝트 범위 및 내용

### 3.1 기능명세

#### 3.1.1 기능 정의
- RV32I 전 명령어(산술/논리/시프트/분기/점프/로드·스토어/LUI·AUIPC) + Zicsr·트랩·FENCE.I 실행.
- PC 측 어셈블러: 입력한 RISC-V 어셈블리를 기계어로 변환(의사명령 li/mv/j/b*z 등 포함), UART 전송.
- PS 모니터: AXI4-Lite 제어 슬레이브로 명령/데이터 메모리 적재, 리셋/실행/단일스텝, 레지스터·PC·커밋·데이터 회신.
- 보드 입출력: MMIO LED(출력), SW·BTN(입력).
- Pmod 주변장치: 2×SPI, 2×I2C, UART, 4채널 PWM, 22비트 GPIO를 0x1000_0000 MMIO 영역에 매핑.

#### 3.1.2 MVP 기능
(표 — 우선순위순. 템플릿의 "페이지" 칼럼은 본 임베디드 프로젝트에 해당 없어 우선순위/메모 중심으로 정리)

| 기능 | 우선순위 | 메모 및 참고사항 |
|---|---|---|
| RV32I 코어(파이프라인+캐시) 실행 | 1 (필수) | 전 명령어 + 트랩, ISS 대조 |
| PC 어셈블러 + UART 통신 | 1 (필수) | GUI/콘솔, 의사명령 지원 |
| PS 모니터(적재/실행/스텝/회신) | 1 (필수) | AXI-Lite @0x4000_0000 |
| MMIO LED/SW/BTN | 2 | 보드 기본 입출력 |
| Zynq SoC 비트스트림(Zybo Z7-20) | 1 (필수) | 합성·구현·타이밍 만족 |

#### 3.1.3 비-MVP 기능
- DDR 적재·실행(보드 DDR 바이트레인 하드웨어 불량으로 보류, JTAG/UART 경로는 영향 없음).
- QSPI 독립 부트(FSBL+BOOT.bin 스크립트 마련).
- Pmod 주변장치 풀세트(SPI/I2C/UART/PWM/GPIO) 및 GUI 주변장치 패널.

### 3.2 서버/DB 환경
본 프로젝트는 호스트 PC와 보드가 UART로 직접 통신하는 단독 임베디드 시스템으로, 별도의 네트워크 서버나 데이터베이스를 사용하지 않는다.

#### 3.2.1 서버 환경
해당 없음(서버리스). 호스트 PC의 Python 프로그램이 시리얼 포트로 보드와 1:1 통신한다. (호스트: Windows + Python 3, pyserial/PySide6)

#### 3.2.2 DB 환경
해당 없음. 프로그램/레지스터 상태는 보드의 온칩 메모리(BRAM/OCM)와 호스트 메모리에서 처리되며 영구 저장소(DB)는 사용하지 않는다.

### 3.3 소프트웨어/하드웨어 환경

#### 3.3.1 소프트웨어 환경
- 설계/합성: Xilinx Vivado 2025.2 (VHDL RTL, IP 패키징, 블록디자인, 합성·구현·비트스트림).
- PS 펌웨어: Xilinx Vitis (ARM Cortex-A9 베어메탈, C).
- 호스트 도구: Python 3 (PySide6 GUI, pyserial), 자체 RISC-V 어셈블러.
- 검증: SystemVerilog 테스트벤치 + Python 명령어집합 시뮬레이터(ISS) 골든모델, Vivado xsim.

#### 3.3.2 하드웨어 환경
- 타깃 보드: Digilent Zybo Z7-20 (Xilinx Zynq-7000 XC7Z020-CLG400, 듀얼코어 Cortex-A9 PS + Artix-7 PL).
- 인터페이스: USB-UART(115200 8N1), Pmod 헤더 JA~JE, 보드 LED/SW/BTN.
- 호스트: PC(USB 시리얼 연결).

### 3.4 전체 구조도
(그림 1. 시스템 아키텍처 — architecture.png 삽입)

PC 어셈블러(GUI/콘솔)가 어셈블리를 기계어로 변환해 UART로 전송하면, Zynq PS의 베어메탈 모니터가 이를 받아 AXI4-Lite(0x4000_0000)로 PL의 RV32 플랫폼을 제어한다. PL에는 RV32 코어 + I$/D$ + 명령/데이터 RAM + MMIO 브리지(LED/SW/BTN + Pmod 주변장치) + AXI-Lite 제어 슬레이브가 들어간다. 실행 결과(레지스터/PC/커밋/데이터)는 역경로로 호스트에 회신된다.

### 3.5 프로젝트 구현 결과
- **합성·구현(Zybo Z7-20, XC7Z020)**: LUT 25,729 / 53,200 (48.4%), FF 38,372 / 106,400 (36.1%), BRAM 12 / 140 (8.6%), DSP 0 / 220 (0%), Slice 12,950 / 13,300 (97.4%). **타이밍 만족**(WNS ≥ 0, hold 위반 없음), DRC 0 에러로 비트스트림 생성.
- **기능 검증**: RV32I 39개 명령어 + 20개 지정 프로그램 + 100개 무작위 프로그램을 ISS 골든모델과 비트 단위 대조 — 전부 PASS. PS 제어경로 회귀(tb_ps_regress)도 PASS.
- **Pmod 주변장치**: JA~JE 40핀을 MMIO 주변장치(2×SPI/2×I2C/UART/PWM/GPIO)로 확장, 양방향 핀 26개 IOBUF 정상 추론, 경계값(BVA) 테스트 35/35 PASS, 비트스트림 타이밍 만족.
- **실보드 동작**: PC GUI에서 어셈블리 입력 → 보드 실행 → 레지스터 변화 회신을 확인(그림 2~3).

## Ⅳ. 결론 및 제언

### 4.1 결론
RV32I 5단 파이프라인 소프트코어를 직접 설계·검증하고 Zynq FPGA에 SoC로 올려, PC에서 입력한 어셈블리가 실제 하드웨어 CPU에서 실행되고 결과가 회신되는 풀스택 시스템을 완성했다. ISS 골든모델 대조로 명령어 정확성을 확보했고, 타이밍을 만족하는 비트스트림으로 실보드 동작까지 확인했다. 또한 모든 Pmod 핀을 어셈블리로 제어 가능한 MMIO 주변장치로 확장하여, 단순 CPU를 넘어 외부 장치를 다루는 확장형 SoC 플랫폼으로 발전시켰다.

### 4.2 제언
- **DDR 적재 기능 복구**: 현재 보드의 DDR 바이트레인 하드웨어 불량으로 대용량 적재가 보류 상태이므로, 정상 보드에서 DDR 경로를 검증하면 큰 프로그램 실행이 가능하다.
- **주변장치/명령 확장**: 인터럽트 컨트롤러, 타이머, M(곱셈/나눗셈) 확장 등을 추가하면 활용 범위가 넓어진다.
- **툴체인 고도화**: 어셈블러에 매크로/레이블 산술·링커 기능을 더하고, GUI에 디스어셈블·메모리 워치 등을 보강하면 교육 도구로서 완성도가 높아진다.
